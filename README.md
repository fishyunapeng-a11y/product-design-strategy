# product-design-strategy

产品设计策略 Skill：将需求背景整理成可讨论、可执行的设计策略文档，并生成用于交互原型制作的 Prompt。

适合产品经理、交互设计师和 UX 设计师在设计启动、页面改版或新功能规划时使用。

## 适用场景

- **页面改版**：明确现有体验问题、改版目标与设计优先级。
- **新功能规划**：梳理用户任务、页面结构和关键交互。
- **小程序、App 与 Web 产品设计**：组织信息架构和页面流转。
- **商业化体验设计**：分析用户价值与业务诉求之间的取舍。
- **设计前期协作**：用结构化文档对齐产品与设计团队的判断。

## 会得到什么

| 产出 | 包含内容 |
| --- | --- |
| 核心问题分析 | 用户痛点、业务诉求、问题优先级与核心机会点 |
| 设计目标与策略 | 一句话目标、目标拆解、衡量指标与设计策略 |
| 信息架构 | 层级定位、页面清单、核心信息、用户行动与流转关系 |
| 交互草稿 Prompt | 页面、流程、组件状态、布局要求及异常与空状态 |

交互草稿模板提供通用版，以及面向 Figma Make、Cursor/Copilot、Stitch/Galileo、GPT-4V/Claude 和简短版的写法。工具名称沿用原模板，不代表已验证所有工具当前版本的兼容性。

## 安装到 Codex

本仓库为私有仓库，下载或克隆前需要拥有访问权限。

### 方法一：让 Codex 安装

在有权访问本仓库的 Codex 环境中发送：

```text
请使用 skill-installer 安装这个仓库根目录的 skill，名称为 product-design-strategy：
https://github.com/fishyunapeng-a11y/product-design-strategy
```

如遇权限问题，先确认 GitHub 连接或本机 Git 身份可以访问该仓库。安装成功后，在下一轮对话中使用。

### 方法二：手动安装

将仓库文件放入 Codex 的 skills 目录，保留原有目录结构。默认位置为：

```text
~/.codex/skills/product-design-strategy/
```

如果自定义了 `CODEX_HOME`，则使用 `$CODEX_HOME/skills/product-design-strategy/`。

已配置 GitHub Git 访问权限、且目标目录尚不存在时，可以运行：

```bash
git clone https://github.com/fishyunapeng-a11y/product-design-strategy.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/product-design-strategy"
```

安装后确认目录中包含 `SKILL.md`、`assets/` 和 `references/`。已有安装时先核对内容，避免覆盖自己的修改。

## 快速开始

在对话中明确指定 skill，并提供需求背景：

```text
请使用 product-design-strategy，帮我输出一份设计策略文档。

产品与平台：一个面向上班族的外卖小程序。
本次范围：优化从购物车到下单成功的流程。
目标用户：午休时间有限、希望快速完成点餐的用户。
现有问题：优惠规则难理解，订单确认页信息拥挤。
业务目标：提升下单完成率，减少优惠相关咨询。
约束条件：保留现有支付链路，本期不新增会员体系。
已有资料：我会提供当前页面截图和需求说明。

请输出核心问题分析、设计目标与策略、信息架构、交互草稿 Prompt。
没有数据支持的指标目标请标为待确认；区分已知事实与分析假设。
交互草稿 Prompt 优先提供通用版。
```

以上为虚构的使用示例，不代表真实产品调研结论。

## 建议准备的输入

| 信息 | 建议提供的内容 |
| --- | --- |
| 业务背景 | 产品定位、本次需求的起因与设计范围 |
| 目标用户 | 主要用户、使用场景和要完成的任务 |
| 当前问题 | 用户反馈、现有页面、流程障碍及相关数据 |
| 设计目标 | 期望改善的用户体验与业务结果 |
| 约束条件 | 技术、周期、资源、合规与不可改动的部分 |
| 参考材料 | PRD、截图、用户研究、设计规范或竞品材料 |
| 输出偏好 | 文档详略、目标原型工具、需要重点展开的部分 |

信息不完整时，skill 会按工作流询问补充。尚未确定的信息可以明确写“待确认”，无需为了填满模板而编造。

## 工作流程

1. **理解需求**：确认背景、痛点、目标与约束。
2. **分析问题**：分别梳理用户体验与业务诉求，识别优先级。
3. **制定策略**：总结目标，拆解为具体策略与衡量方式。
4. **组织信息架构**：选择适合需求的层级，明确页面职责和流转。
5. **编写交互草稿 Prompt**：描述页面、关键流程、组件和边界状态。
6. **输出文档**：按设计策略模板组织结果，供团队讨论与后续原型制作。

## 使用边界

- 主要产出是策略文档与交互草稿 Prompt；不会仅凭安装就自动创建 Figma 文件、可运行原型或生产代码。
- 输出依赖所提供材料，不能代替用户研究、数据分析或团队评审。
- 业务事实、指标基线与目标值应有来源；缺少依据时标注假设或待确认项。
- 把 Prompt 交给原型工具后，仍需检查页面完整性、交互状态、可访问性和实际可用性。
- 使用业务资料时，遵循所在团队的数据使用与分享要求。

## 常见问题

**已经安装，但没有按预期生成文档？**

先在提示中明确写“使用 product-design-strategy”，并确认 `SKILL.md` 及配套资源存在于安装目录。随后补充本次设计范围和希望输出的章节。

**必须一次生成全部工具版本的 Prompt 吗？**

可以明确指定只要通用版，或只展开实际使用的工具版本，减少重复内容。

**如何修改模板？**

在 `assets/` 中修改对应模板。若希望其他环境也获得相同内容，将修改提交到本仓库，再同步各环境的安装副本。

**其他 AI 工具可以使用吗？**

可以手动参考 Markdown 文档与模板；是否支持自动发现和调用 skill，取决于目标工具的机制，需要单独确认。
